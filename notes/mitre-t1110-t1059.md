# MITRE ATT&CK — detection notes (soc-detection-lab)

## T1110 — Brute Force
- Tactic: Credential Access (adversary wants to obtain credentials)
- Sub-techniques (selected):
  - .001 Password Guessing — many passwords against one account; trips lockout
  - .003 Password Spraying — one password against many accounts; evades lockout,
    because failed-attempt counters are tracked per account, not per attacker
- Detection: DET0463 (multi-platform correlation of authentication failures)
  - AN1276: series of auth failures followed by success from the same IP/user
  - AN1278: multiple failed authentications in system logs (sshd)
    → this is what my auth.log parser from log-parser-toolkit implements
- Telemetry: Windows Event ID 4625 (failed logon) / Linux auth.log (sshd)
- Rule (Saturday, Wazuh): threshold of 4625 / failed sshd events from a single
  source within a time window

## T1059 — Command and Scripting Interpreter
- Tactic: Execution (code execution via built-in interpreters)
- Sub-techniques (selected):
  - .001 PowerShell (Windows)
  - .004 Unix Shell (Linux)
- Key insight: an interpreter is a system feature, not a vulnerability — it cannot
  be patched, so detection must be behavioral (context), not signature-based
- Detection: DET0516 (behavioral detection of interpreter abuse)
  - AN1428 (Win): interpreter launched outside admin working hours / from an
    unusual user context / with encoded or obfuscated arguments
  - AN1429 (Linux): shell spawned by a user/process that normally doesn't do so;
    chains involving netcat/curl/ssh
- Telemetry: process creation + FULL command line
  → Sysmon Event ID 1 (includes command line) vs native 4688 (no command line
    by default) → this is why Sysmon is in the plan
- Difference vs T1110: there it's arithmetic (counting events in a window),
  here it's context anomaly (who, when, parent process, arguments)
